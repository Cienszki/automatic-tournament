# Dev setup on a new machine

Everything you need is in git **except secrets** (env files) and rebuildable artifacts
(`node_modules`, `.next`). Clone the repo, install deps, and copy the secret files listed
at the bottom. Node 20+ and git are required.

```bash
git clone https://github.com/Cienszki/automatic-tournament.git
cd automatic-tournament
git checkout feature/multi-tournament-platform   # the active branch (bot + platform work)
```

## 1. Web app (Next.js)

```bash
npm install
# copy .env.local (see "Files to transfer manually")
npm run dev          # local dev
```

Deploy (unchanged): `firebase deploy --only hosting --project tournament-tracker-f35tb`
(Firebase CLI must be authed: `firebase login`).

## 2. Bot worker

The bot lives in `bot-worker/`. **Only compiled `dist/*.js` is committed** (no TS source) —
edit `dist/` directly. `dist/` is gitignored but force-tracked, so **new** files under
`bot-worker/dist/` must be added with `git add -f <file>` (modifications to existing tracked
files commit normally).

### To DEPLOY the bot you need nothing locally
Railway is GitHub-integrated to `feature/multi-tournament-platform`. Pushing that branch
rebuilds the bot (the Dockerfile runs `npm install` + the steam-resources proto surgery on
Railway). So: edit `bot-worker/dist/*.js`, commit, push the branch → Railway redeploys.
Bot credentials + `FIREBASE_SERVICE_ACCOUNT_BASE64` are Railway **environment variables**,
not files.

### To RUN/TEST the bot locally (diagnose.js, _score-change-test.js)
Plain `npm install` is **not** enough — node-dota2 + steam need protobufjs@4 nested in two
places and a patched `CSODOTALobby` proto, or the bot can't see lobby members. `setup-local.js`
reproduces exactly what the Dockerfile does:

```bash
cd bot-worker
npm install
npm run setup:local        # == node setup-local.js  (idempotent; needs network once)
# copy bot-worker/.env (see below), then:
node dist/diagnose.js --bot-id=<firestoreBotAccountId>            # GC connection check
node dist/_score-change-test.js --bot-id=<firestoreBotAccountId>  # score/penalty harness
```

⚠️ Pause the Railway service (or use an idle bot) before logging one in locally — the same
Steam account logged in twice kicks itself.

## Files to transfer manually (gitignored secrets — NOT in the repo)

Copy these from this machine (all gitignored). `.env.example` templates are committed where
useful.

| File | Needed for | Notes |
|---|---|---|
| `.env.local` | web app (local dev/deploy) | Firebase client keys, `CRON_SECRET`, `STEAM_API_KEY`, `OPENDOTA_API_KEY`, `STRATZ_API_KEY`, `TWITCH_*`, `FIREBASE_SERVICE_ACCOUNT_BASE64`. |
| `bot-worker/.env` | bot local run/test | Mainly `FIREBASE_SERVICE_ACCOUNT_BASE64`. See `bot-worker/.env.example`. Not needed for deploy. |
| `.firebase/tournament-tracker-f35tb/functions/.env*` | Firebase Functions build | Often regenerated by the framework build; copy if a deploy complains. |

Rebuildable — do **not** transfer: `node_modules/` (run `npm install`), `.next/` (build output),
`bot-worker/node_modules/` (run `npm install` + `npm run setup:local`).

## Deploy cheat-sheet
- **Bot:** commit `bot-worker/dist/*` → `git push origin feature/multi-tournament-platform` → Railway rebuilds. Don't deploy while a game is live (restarts all runners).
- **Web:** `firebase deploy --only hosting --project tournament-tracker-f35tb`.
