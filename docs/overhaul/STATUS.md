## Decisions that changed the plan (owner, 2026-11-13)

1. **Firestore is not required.** The tournament platform moves to PostgreSQL with a clean structure (`ARCHITECTURE.md` ADR-04). Firebase keeps sign-in and files. Fable chose Supabase (free plan, Frankfurt) as the host, used as plain PostgreSQL.
2. **Production does not change until the new platform is ready.** This includes the two security fixes (questions 1 and 4). The new platform is built on `overhaul` beside the old site and takes over one tournament at a time, starting with archived ones (ADR-15). The brief's rules still hold: no deploy by agents, no writes to production Firestore, no script with production credentials. The brief's rule "change the Firestore schema only additively" no longer applies, because the Firestore schema is not changed at all.
3. **Letnia becomes an ordinary tournament** at `/letnia`, imported into the same tables as the others (WP-33). It is not reachable today, so it is the first tournament to go live on the new platform.
4. **Free or basic plans until there is income.** Every service starts free; `COSTS.md` gives the triggers for paying.
5. **Organizers choose their tie-breakers and their order,** can use tiebreaker matches, and can rank teams from different groups for playoff places and seeding (ADR-11, WP-13a, WP-34).
6. **Region per tournament** is not built now. The design keeps it possible, and the reasons are in ADR-17.
7. **PDL S2 is the real-world test.** It is mirrored onto the new platform while it is played on the old site, compared every day (WP-39), and then moved to the new platform between two match days while still running (WP-37). The owner handles the players. The card game must work there, so it is moved as it is (WP-40).
8. **No commercial use today.** Vercel's free plan is allowed; the paid plan starts with the first income.
9. **The old site is frozen for features** from 2026-11-13: fixes only.
10. **The owner prefers the terminal to websites.** Setup steps are commands or scripts wherever the service allows it; `SETUP_STAGING.md` follows this.
11. **Fantasy:** the role-based formula is the default for new tournaments.

Added by the owner on 2026-11-22:

12. **The result first, the details later.** A game's winner is shown as soon as the bot sees the game end (the bot reads it from the Dota lobby); OpenDota fills the statistics when it has the match. Written into WP-13b, WP-21 and `ARCHITECTURE.md` section 2.3.
13. **PDL S2 will still be played when the platform is complete on staging,** so it stays the season that is mirrored, compared daily and then moved (WP-39, WP-37).
14. **Production fixes are carried into `overhaul`.** Production gained four changes on 2026-11-19 (caster corner, Steam without the API key, caster notifications and muting, account merge); they were merged into `overhaul` on 2026-11-22 and their behaviours added to WP-38's acceptance. 15. **Themes to choose from.** Detailed customization is too much for many organizers, and not all are good at visual design. So the look screen offers a list of themes: complete preset values for every customization setting (more settings will be added). Examples: "sakura" for Wiosenna, "synthwave" for Letnia, one for PDL and PDL S2 (name to be proposed), and for the owner's future tournaments cyberpunk, pixel art, ancient Rome, Chinese mythology, steampunk, brutalist, Studio Ghibli, ocean reef, Victorian and more. A theme may bring its own fonts, button shapes, background images, table styles and decorations. Any user can tinker with the settings and save the result as their own theme, which other users may use. A really rich theme, with more customized, is a premium service in the most expensive plan. This goes beyond today's design (`ORGANIZER_UX.md` section 6.3: about eight presets, and layout never editable), so S9 revises section 6.3, WP-27 and WP-45 and adds the theme library, user themes and sharing.

The obvious first imports are every The International and many more tier-1 Dota 2 tournaments (professional leagues, which OpenDota does list, unlike ours: question 41). S9 adds a work package.
17. **Other games, far in the future.** If it becomes possible, the platform branches out beyond Dota 2. The automation (lobbies, results) will be the hard part, but some games should allow it. Nothing is built for it now; new design should not tie the core (tournaments, stages, teams, matches, results) to Dota where it costs nothing to keep it general. S9 records this in `ARCHITECTURE.md`, next to the record on regions (ADR-17).

      - *Polling.* Every tournament with an unfinished match is read every 5 minutes (one call per league for its newest games; 288 calls a day per tournament against Valve's 100,000), plus a full sweep once a day. A window around the scheduled time was considered and dropped: it saves almost nothing and misses games played earlier than planned.
